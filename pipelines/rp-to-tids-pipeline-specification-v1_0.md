# ⭐ **1 — Purpose of the Pipeline**

This specification defines the **canonical sequencing** between:

- **NDH‑RESEARCH‑PILOT (RP)** — the altitude‑setting, membrane‑defining, drift‑stabilizing diagnostic layer  
- **NDH‑TIDS** — the comparative geometry engine that performs reversible contrastive mapping

The pipeline ensures:

- altitude coherence  
- membrane integrity  
- drift stabilization  
- recursion prevention  
- Harmony protection  
- SID‑safe comparative geometry  
- reversible mapping guarantees  

This is the **official RP → TIDS transition architecture**.

# ⭐ **2 — Pipeline Overview**

The pipeline consists of **five altitude‑dependent phases**:

1. **Altitude Selection (RP)**  
2. **Membrane Definition (RP)**  
3. **Conceptual Domain Framing (RP)**  
4. **Drift Stabilization (RP)**  
5. **Comparative Geometry Execution (TIDS)**  

RP prepares the substrate.  
TIDS performs the geometry.

# ⭐ **9 — TIDS Constraints (v2.0 Integration)**

TIDS v2.0 enforces:

### **Constraint 1 — Harmony is always the reference object**  
Harmony cannot be:

- categorized  
- compared  
- ingested  
- normalized  
- elevated  

Harmony is a **boundary**, not an operand.

### **Constraint 2 — External systems must be normalized**  
Normalization requires RP’s altitude and membrane definitions.

### **Constraint 3 — Comparative geometry must be reversible**  
Reversibility requires RP’s drift stabilization.

### **Constraint 4 — Drift signatures must be stabilized**  
Only RP‑stabilized drift may enter TIDS.

### **Constraint 5 — Stability envelopes must preserve Harmony**  
RP ensures membrane integrity; TIDS encodes the envelope.
