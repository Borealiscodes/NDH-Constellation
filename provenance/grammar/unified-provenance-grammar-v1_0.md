# ⭐ **1 — Grammar Classification**

**Grammar Type:**  
- Unified Provenance Grammar  
- Altitude 7 (Substrate)  
- Non‑Activating  
- Non‑Orbital  
- Stabilization‑Corridor Compliant  
- MERA Dissolution‑Rules Phase  

**Purpose:**  
Define the **rules**, **syntax**, and **constraints** governing:

- provenance formation  
- lineage recording  
- stabilization behavior  
- trauma‑informed overlays  
- governance curvature alignment  
- multi‑altitude recursive alignment (MERA)  

This grammar does **not** activate orbital routing, orbital geometry, or orbital provenance.

---

# ⭐ **2 — Core Grammar Rules (Invariant Layer)**  
### *These rules apply across all altitudes and lanes.*

| Rule | Description |
|------|-------------|
| **Rule 1 — Provenance Must Be Non‑Activating** | Provenance may record geometry but never execute it. |
| **Rule 2 — Provenance Must Be Altitude‑Bounded** | Provenance must specify altitude context explicitly. |
| **Rule 3 — Provenance Must Be Lane‑Separated** | Pilot, Simulation, and Governed lanes must not mix. |
| **Rule 4 — Provenance Must Be Reversible** | All provenance states must support reversal. |
| **Rule 5 — Provenance Must Be Drift‑Safe** | Provenance cannot introduce drift into geometry or governance. |
| **Rule 6 — Provenance Must Be Trauma‑Informed** | Provenance must respect TISD ethical overlays. |
| **Rule 7 — Provenance Must Be Governance‑Aligned** | Provenance must reflect Governance Spine v1.3. |
| **Rule 8 — Provenance Must Be MERA‑Aligned** | Provenance must follow MERA phases (Center → Expansion → Spiral → Return → Dissolution). |

These are the **immutable grammar invariants**.

---

# ⭐ **3 — Syntax Grammar (Structural Layer)**  
### *Defines how provenance statements must be structured.*

### **3.1 Provenance Statement Format**

Every provenance statement must follow:

```
<altitude>::<lane>::<geometry_state>::<governance_state>::<provenance_role>
```

Example (non‑activating):

```
A6::Governed::Curvature_Aligned::Authority_Sealed::Return_Stabilization
```

### **3.2 Required Fields**

Each provenance entry must include:

- **altitude**  
- **lane**  
- **geometry state**  
- **governance state**  
- **provenance role**  
- **MERA phase**  
- **stabilization‑corridor compliance tag**  

### **3.3 Prohibited Fields**

Provenance entries may **not** include:

- orbital routing  
- orbital geometry  
- orbital provenance grammar  
- runtime activation commands  
- expressive geometry injection  
- cognitive geometry injection  

This ensures **non‑activation**.
