# 🛑 **SID Header Standard v2.0 — Disclaimer (Non‑SID Artifact)**

This document defines the rules, boundaries, and placement logic for SID Headers across all NDH subsystems.  
It is a **governance‑adjacent specification** and therefore **MUST NOT receive a SID Header itself**.

SID Headers are **subsystem‑local descriptors** and MUST NOT be applied to:

- standards  
- specifications  
- indexes  
- comparative‑geometry rulebooks  
- constellation‑grade meta‑documents  

This Standard is:

- non‑activating  
- non‑constitutional  
- non‑governance  
- non‑directive  

It defines **how SID Headers behave**; it does **not** itself participate in SID lineage.

All SID Headers created under this Standard MUST follow v2.0 rules and MUST be placed in the subsystem they describe.  
All multi‑system analysis artifacts MUST be placed in **NDH‑CONSTELLATION** under comparative‑geometry analysis.

# ⭐ **2 — SID Header Placement Rules (v2.0)**

## **Rule 1 — SID Headers Are Subsystem‑Local**

SID Headers MUST be placed in the subsystem they describe.

| Subsystem | SID Header |
|----------|------------|
| NDH‑AGL | SID‑AGL‑v2.0 |
| NDH‑TIDS | SID‑TIDS‑v2.0 |
| NDH‑REL | SID‑REL‑v2.0 |
| NDH‑PLATFORMS | SID‑PLATFORMS‑v2.0 |
| NDH‑COORDINATION | SID‑COORDINATION‑v2.0 |
| SCI‑80 | SID‑SCI80‑v2.0 |

SID Headers MUST NOT be applied to:

- NDH‑CONSTELLATION  
- standards  
- indexes  
- comparative‑geometry rulebooks  
- governance‑adjacent documents

## **Rule 2 — Multi‑System Analysis MUST Live in NDH‑CONSTELLATION**

Any artifact touching more than one subsystem MUST be placed in:

```
NDH-Constellation/comparative-geometry/analysis/
```

### ASCII Diagram — Multi‑System Placement

```
Subsystem-local analysis → stays in subsystem
Cross-system analysis    → moves to NDH-Constellation
```

### Examples of multi‑system analysis:

- AGL ↔ TIDS  
- AGL ↔ TIDS ↔ Phase‑11  
- TIDS ↔ SCI‑80  
- AGL ↔ SCI‑80  
- NDH‑Research‑Pilot ↔ SCI‑80  
- NDH‑CONSTELLATION ↔ SCI‑80  
- any analysis involving the Directive Index (absent/sealed)

## **Rule 3 — SCI‑80 Cannot Host Comparative Geometry**

SCI‑80 is:

- dormant  
- sealed  
- reflection‑altitude  
- posture‑aligned  
- non‑directive  
- non‑ingestion  
- non‑comparative  
- dependent on AGL/TIDS stability  
- referenced by constellation stability geometry  

Therefore:

### SCI‑80 MUST NOT host:
- comparative geometry  
- movement rules  
- altitude boundaries  
- stability envelopes  
- governance adjacency  

Any artifact touching SCI‑80 MUST be placed at **NDH‑CONSTELLATION altitude**.

---

## **Rule 4 — SID Headers MUST Declare SCI‑80 Dependencies**

SID‑SCI80‑v2.0 MUST explicitly state:

- SCI‑80 is sealed  
- SCI‑80 is dormant  
- SCI‑80 cannot ingest comparative geometry  
- SCI‑80 cannot ingest constraints geometry  
- SCI‑80 cannot ingest translation geometry  
- SCI‑80 requires binding directives (absent + sealed)  
- SCI‑80 depends on AGL/TIDS stability envelopes  
- SCI‑80 is referenced by constellation stability geometry  

This prevents accidental activation.

# ⭐ **5 — Directive Index (Absent/Sealed) Rules**

### **Rule A — Absent Index = No Binding Directives**  
SCI‑80 cannot activate.

### **Rule B — Sealed Index = No Governance Elevation**  
Comparative geometry cannot elevate into governance.

### **Rule C — Micro‑Directives Allowed**  
Only in operator‑lane scaffolding.

### **Rule D — SCI‑80 Requires Binding Directives**  
Therefore SCI‑80 remains dormant.

### **Rule E — Comparative Geometry Cannot Bind SCI‑80**  
SCI‑80 is reflection‑altitude, not comparative‑altitude.
